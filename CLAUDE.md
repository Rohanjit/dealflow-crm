# Dealflow — project brief for Claude

Read this first in every session. The full product scope is in `docs/scope-v1.md`; this file covers how we work and how the code is organised.

## Working model

- Shobhit (product owner, ex-investment banker) makes product decisions and answers questions. He does not write code.
- Claude writes all code, tests it, and pushes to this repo. Each module is built on its own branch and Claude merges it into `main` once it's tested (Shobhit's call, 29 Sep 2026); no pull request review step.
- Ask product questions **one at a time**. Technical choices are Claude's to make, but record them in this file.
- The repo stays **private** until all six V1 modules are done.
- Build order (finish each before the next): Foundation + Investors → Contacts → Outreach → Active Deals → Tasks & Reminders → Vault.
- Anything outside V1 scope goes to the "Not in V1" list in `docs/scope-v1.md`. Don't build it without a decision.

## Stack

- `backend/`: Python 3.11+, Django 5.1, Django REST Framework, django-filter, openpyxl. Served by gunicorn; the built frontend is served by Django through whitenoise, so the app ships as **one container**.
- `frontend/`: React + TypeScript, built with Vite. Mantine for UI components, TanStack Query for data fetching, React Router.
- Database: SQLite by default (file in the data volume); Postgres when `DATABASE_URL` is set.
- `docker-compose.yml`: `app` service, `scheduler` service (same image, runs daily backups), optional `db` (Postgres) behind a compose profile.
- Auth: Django session cookies + CSRF (the SPA and the API share one origin). No tokens in localStorage.

## Architecture decisions

1. **Field registry drives the UI.** Each module declares its fields once in the backend (`<app>/fields.py`: key, label, group, type, dropdown list, required). The API serves this schema merged with the firm's on/off switches, and the frontend renders list columns, detail pages, forms, filters, import mapping and export columns from it. New modules reuse the same generic screens.
2. **Field types:** text, longtext, url, email, phone, integer, decimal, percent, date, boolean, tri-state (yes/no/unknown), fixed choice, dropdown (single/multi, from editable lists), user, money, tags, link (a record in another module), birthday (day + month, year optional).
3. **Money** is stored as three columns: amount (decimal), currency (ISO code) and unit (e.g. `Cr`, `Lakh`, `Mn`, `Bn`, `K`, or none). No conversion.
4. **Editable dropdowns** are `ChoiceList` + `ChoiceOption` rows. Records point at option IDs, so renames propagate. "Removing" an option deactivates it: existing records keep it, new records can't pick it.
5. **Permissions** are per role, per module: view / create / edit / delete, plus global flags: manage users, manage settings, restore archive. The built-in Admin role has everything and can't be edited or deleted.
6. **Archive:** every main record has `archived_at` / `archived_by`. API querysets hide archived rows. Archiving needs the module's delete permission; restoring needs the "Restore from archive" flag; permanent deletion is admin-only.
7. **Stamps:** every main record has `created_by/at` and `updated_by/at`, set automatically by the API.
8. **Per-user preferences** (date format, number grouping) live on the user and are applied only when formatting in the frontend. The API always sends ISO dates and plain numbers.
9. **Backups** are a zip of a Django `dumpdata` export plus uploaded files, so they restore on either SQLite or Postgres.
10. **Records API** is generic: `/api/m/<module>/` (list, create), `/api/m/<module>/<id>/` (read, PATCH, DELETE = archive), plus `export/` and `import/upload|check|commit/`. Registering a module (`<app>/fields.py` → `core.registry.register`) and adding it to `core.modules.BUILT_MODULES` is all a new module needs for the standard screens; the frontend renders from `/api/schema/`.
11. **`Record.objects` returns archived rows too**, so backups (`dumpdata`) include them. API querysets filter `archived_at__isnull=True` explicitly.
12. **Money** also keeps a hidden `<key>_value` column (amount × unit multiplier) for sorting and range filters. Comparisons only happen within one currency; sorting groups by currency first.
13. **Who can do what, beyond module permissions:** restoring from the Archive needs the "Restore from archive" flag; permanent deletion, role editing and backups (list, download, restore, schedule) are Admin-only. Users with "Manage users" can't create, edit or promote Admin accounts. At least one active Admin must always remain.
14. **Invites** are one-time links valid 7 days. Temporary passwords (admin-created accounts and resets) force a password change at next sign-in and end the person's other sessions.
15. **Import** keeps the parsed file under `DATA_DIR/imports/<token>.json` between steps (24 h). Duplicate warnings compare normalised firm names (generic words like "Ventures", "Capital" ignored) and website domains. Unknown dropdown values are left blank with a warning, unless someone with "Manage settings" ticks "add missing values". Slashed dates are read in the importing user's date format. Money cells understand "₹ 50 Cr", "$5mn", and a currency/unit taken from the column header.
16. **Export** writes one numeric column per money field plus a "– currency & unit" column; import recognises that pair, so exports round-trip.
17. **Starter data:** migrations seed the Admin role, an editable "Member" role (view/create/edit everywhere, no delete), and default dropdown lists for the modules that exist. Each later module seeds its own lists in its own migration.
18. **Scheduler** (`manage.py run_scheduler`) checks every minute and takes the daily backup at the hour set in Settings (default 02:00 server time), keeping the newest N of each kind (daily / manual / pre-restore). A restore takes a "pre-restore" safety backup first and signs everyone out. On Postgres the load checks foreign keys at commit (a contact can point at an Outreach company loaded after it).
19. Column choices on list pages are the only thing kept in browser storage (per user, per browser).
20. **Links** (`type="link"`, e.g. a contact's "Firm / company") keep one FK column per possible target: `targets={"investors": "investor"}`; the company side joins as a second target when Outreach lands, on the same field. The API sends `{module, id, title, archived}` and accepts that or `"investors:5"`. Filters: `?firm=investors:5,investors:9` and `?firm_type=investors|none` (the side switch above the list). A record can keep a link to an archived record but can't be newly linked to one; permanently deleting the target unlinks. Pickers use `/api/lookup/<module>/`, open to anyone who can view that module or can create/edit in a module that links to it. Link filters apply even when the field is switched off, and fields that other screens depend on are `always_on`.
21. **Birthday** is stored as `MM-DD` plus an optional `<key>_year` column, and sent as `MM-DD` or `YYYY-MM-DD`.
22. **Related sections** on detail pages are declared on the parent module (`sections=[{module, link_field, columns, order}]`), e.g. an investor's Linked contacts. Their status in `/api/schema/` is ready / coming (module not built yet) / hidden (no access).
23. **Sorting** takes several keys (`?ordering=-primary_contact,decision_level,full_name`). Empty values sort last; dropdowns sort by the list's own order (e.g. seniority), not alphabetically.
24. **Contacts:** the firm link is optional (lawyers, advisers and introducers needn't belong to a firm). "Primary point of contact" is a flag, and several per firm are allowed. "Introduced by" is free text. Import duplicates: same email, mobile (last 10 digits), LinkedIn profile, or same name at the same firm.
25. **Import, more:** several columns can feed one text field ("First name" + "Last name" → Full name). Link cells match an existing record by exact name, then by normalised name (for investors the generic words are ignored, so "Blume" finds "Blume Ventures"); names matching several records are left blank with a warning. Unmatched names can optionally be created as new records, only by people who can create in that module.
26. The Vite build is served through WhiteNoise, which indexes files at start-up: restart the server after rebuilding the frontend (automatic when `DJANGO_DEBUG=1`).
27. **Outreach is company level** (Shobhit, 29 Sep 2026): `outreach.Company` is recorded once; each approach is an `outreach.Outreach` attempt with a required `company` FK. Both live in the `outreach` app and register two modules: `companies` and `outreach`. The menu shows one Outreach item with Pipeline / Companies tabs.
28. **Company-level fields on attempts** use `proxy()` (FieldDef `via="company"`, `via_module="companies"`): same key and type as on the company; reads, filters, sorting, search, export and import go through the FK, and saves land on the company, so every attempt (and later every deal) shares them. Their on/off switches belong to Companies. Imports never blank a known company detail from an empty cell.
29. **Derived permissions:** `core.modules.DERIVED_PERMISSIONS` — companies have no permission row of their own and allow whatever Outreach or Active Deals allows. `Role.module_perms()` and `User.can()` include them.
30. **Pipelines** (`ModuleDef.pipeline = PipelineDef(...)`, logic in `core/pipeline.py`): `stage` holds one of the fixed stages and `status` is open / on_hold / lost, so an exit keeps the stage it happened at. Lost needs a reason; on hold needs a reason and a revisit date (not enforced on import). Changing the stage reopens a paused or lost record; resuming keeps the stage. `stage_entered` updates on every stage change; exit details clear when they stop applying. Every change writes a log entry. The app never types stage or status into a form: the board and the stage bar send PATCHes.
31. **Interaction log:** `core.Note` (module + record id), kinds note / call / meeting / email / stage. `/api/m/<module>/<id>/notes/` (view to read, edit permission to add); authors or admins edit or delete their own notes; stage entries are fixed. Enabled per module with `timeline=True`. Permanently deleting a record deletes its log.
32. **Titles:** a module can be named through a link (`title_path="company__name"`, `title_fn`), used by search, lookups, archive and import review.
33. **Won mandates** stay in Outreach at "Mandate won" until Active Deals exists; that module will create a deal for each (including ones won earlier).
34. List quick switches can be explicit (`segment_param` / `segment_options` / `segment_default`, e.g. Outreach's Active / Won / On hold / Lost / All). With no parameter the API returns everything; the app sends the default, and the board ignores it.
35. **Exits are described per pipeline** (`core.registry.Exit`: label, action, done, paused, reason_field, date_field, tone), so screens and log entries read "Company withdrew", "Withdrawn by company at Term sheet", "Declined at NDA signed · Valuation mismatch". Paused exits are resumed; the rest are reopened. Reason and date fields have `pipeline_role="exit"`. Pipelines can group stages into phases (`groups`), shown on the stage bar, board and dashboard.
36. **Mandate won → deal:** `core.pipeline.stage_changed` is sent after every stage/status change; `deals/signals.py` turns an outreach attempt reaching Mandate won into a deal at Data collection (once per attempt, archived deals included; migration `deals/0003` did the same for mandates won earlier). Carried over: company, transaction type, source, lead banker, expected size → target raise, proposed retainer → agreed retainer, proposed success fee → success fee %, final agreed fees → agreed fees, tags; mandate date = the day it was won. The deal's `outreach` link is read-only.
37. **Deals** share company details through proxies like outreach, plus a company **Geography** field (added for investor matching). Deal team = lead banker + four multi-user fields (MD, VP, Associate, Analyst); `?team=me` finds deals someone is on. Instrument is a fixed choice (Equity, CCPS, CCD, Debt, Mix). Deal exits need no reason (the optional note is logged). Target close date and mandate expiry are always on because the home page uses them. Deals aren't imported from files (`importable=False`): import won mandates through Outreach instead.
38. **Investor tracker** is its own record type, `deal_investors` (`deals.DealInvestor`): a pipeline (Identified → … → Selected; exits Declined with reason, No response) with its own log, permissions derived from Active Deals, left out of global search (`in_search=False`). One entry per investor per deal (checked on create and on restore). Entries of archived deals drop out of lists; permanently deleting a deal deletes its tracker (and logs); an investor on a tracker can't be purged. The deal page shows it as a panel (`section.panel = "tracker"`) with funnel counts ("reached" = at or past each stage, exits included); an investor's Deal history lists its entries.
39. **Investor matching** (`deals/matching.py`, `GET /api/deals/<id>/matches/`, needs view on deals and investors): sector 25, ticket vs raise 20 (same currency only; min above the raise = no, max under 10% of it = half), stage 15, geography 15 ("Global" matches all), equity/debt 15 (CCPS/CCD count as equity), actively deploying 10. Unknowns on either side score a little instead of zero. Archived and already-tracked investors are left out.
40. **Home dashboard** (`GET /api/dashboard/`, needs deals view): active deals by stage, tiles for active / on hold / closed / withdrawn or dropped, open deals whose target close date is within the window or past, and open or paused mandates expiring within the window or already expired. The window is `FirmSettings.dashboard_days` (default 30, Settings > Firm).
41. **Field kinds added with Active Deals:** links and users can take several values (`multi=True`; many-to-many per target, filtered through a subquery so rows don't repeat, exported as names joined by commas); `readonly` fields are shown but never taken from forms or imports; `datetime` (date + optional time, `<key>_time` column, API `YYYY-MM-DD` or `YYYY-MM-DDTHH:MM`) for Tasks. Link pickers only offer "add new" for modules named by plain text. A record deleted for good takes its log with it (`core/signals.py`), including records removed in a cascade.
42. **Board for long pipelines:** with more than eight stages, empty columns fold into narrow strips so the whole board fits; while a card is dragged its hit box narrows to a strip under the pointer (set in `onBeforeCapture`), because the drag library otherwise picks the furthest of several narrow columns the card covers.
43. **Tasks** (`tasks.Task`): title, description, due (`datetime`: date + optional time), priority (default Medium) and status (default Open) via FieldDef `default`, assignee (`default_me`: new tasks start with whoever adds them; can be left unassigned), `related` link to an outreach attempt, deal, investor or contact (SET_NULL on permanent deletion), read-only Created by and Completed on (set when marked done, cleared when reopened). Views: `?view=mine` (the app's default: my unfinished tasks, shown grouped as Overdue / Today / Upcoming / No due date), `open`, `done`, `all`. Records show their tasks in a panel (`section.panel = "tasks"`) with tick-to-complete and Undo. Not imported from files.
44. **Reminders are in-app** (`GET /api/tasks/alerts/`, polled every minute): my unfinished tasks overdue or due today, judged on the firm's clock (server time zone), which is also sent as `now` so every screen groups tasks the same way. A date-only task is due all that day and overdue the next; a timed task is overdue once its time passes. The header bell shows the count and the list; notices appear on opening the app (overdue count), when a timed task falls due, and when someone else assigns you a task. Notifications and modals render inside the router, so they can hold links.
45. **Vault documents** (`vault.Document`): title, category (editable list), description, and `tagged` (a multi-link to companies, outreach attempts, deals and investors). Files live in `MEDIA_ROOT/vault/YYYY/MM/<random>.<ext>`; the original name, type label, size, content type and SHA-256 are stored as data. Uploads go through `POST /api/vault/upload/` (several files, shared details, one refused file stores nothing); the generic create is refused. Accepted formats are an allowlist checked against each file's first bytes (`vault/files.py`); 50 MB per file (`DEALFLOW_VAULT_MAX_FILE_MB`). Downloads (`/api/vault/<id>/download/`) are attachments with `nosniff` and `no-store`; PDFs and images may open inline (images sandboxed). Deleting for good removes the file; backups already carry `MEDIA_ROOT`. Record pages show documents in a panel (`section.panel = "documents"`, `?about=deals:5`): a deal or outreach attempt also shows documents tagged to its company, and a company shows those of its outreach and deals.
46. **Vault PIN** (`vault/pin.py`): 4–8 digits, not repeated or consecutive, hashed with Django's password hasher on the user (`vault_pin`). The first PIN needs the account password; changing needs the current PIN; people who manage users can clear it (not an admin's unless they're admin). Five wrong PINs (or passwords) lock that person's Vault for 15 minutes everywhere. Opening it stores `vault_until` in the session; every Vault request slides it 15 minutes; Lock clears it.
47. **Module gates:** `ModuleDef.gate(request)` runs after the role check on every generic read and write (list, detail, create, edit, archive, export, lookup, notes, archive list and restore). The Vault's gate is its PIN; refusals carry `code` `vault_pin_required` / `vault_locked` / `vault_locked_out`, and the app shows the PIN screen (or an inline PIN box in record panels) when it sees them. A locked Vault keeps document titles out of global search and the Archive.
48. **Look and feel** (Shobhit, 19 Oct 2026: "a Notion UI with micro interactions"): a calm, document-like workspace inspired by Notion, not a copy (no Notion branding). Tokens and Mantine defaults live in `frontend/src/theme.ts` (warm greys, one blue for actions kept under the colour name `navy`, small radii, layered shadows, ink-coloured links); every reusable style and animation is in `styles.css` under `df-*` classes; shared pieces (`PageHeader`, module and field-type icons, `Skeleton`/`PageSkeleton`/`TableSkeleton`, `Reveal`, `CountUp`) are in `components/ui.tsx`. Frame: a sidebar (firm menu, Search, Home, Workspace modules with a hover "+" to add, Archive, Settings) that folds away, a slim sticky top bar with the reminders bell, and a search palette on ⌘K / Ctrl K or "/" (`layout/SearchPalette.tsx`: quick jumps and "new" actions when empty, global search when typing, arrow keys and Enter). Record pages are pages: icon, big title, facts line, stage bar, then properties as rows grouped under toggles with empty ones folded away, and panels separated by hairlines. Lists are database tables with field-type icons, an "Open" chip on hover and a "+ New" row; dropdown options show as coloured tags whose colour follows the option id (`OptionTag`). Boards have tag-style column headers, cards that lift and tilt while dragged, highlighted drop targets and "+ New" per stage (`?stage=` pre-fills it). Motion: see decision 58. The sidebar's open/closed state isn't stored (decision 19 still holds).
49. **One install, one firm or one person** (Shobhit, 19 Oct 2026): Dealflow stays self-hosted, on a firm's server or someone's own computer. The setup wizard asks "For my firm" or "Just me" (`FirmSettings.workspace_kind`; for "Just me" the name is optional and the sidebar shows the person's name; team prompts are hidden; Settings > Firm can switch it). No open sign-up and no separate workspaces on one install.
50. **Guest mode** (`core/guest.py`, `core/sample.py`; Shobhit, 19 Oct 2026): before an install is set up, "Look around first" (`POST /api/guest/start/`) saves the empty install to `DATA_DIR/pristine.json`, loads a sample firm (investors, contacts, companies, outreach at every stage including lost and on hold, mandates won turned into deals, trackers, a closed deal, tasks for the guest, notes, five PDF documents) and signs the visitor in as its Guest (Admin role, no password; sample PIN 2580 shown on the Vault screen, can't be changed and doesn't lock). `FirmSettings.sample_loaded_at` marks the sample. While it's loaded, people-and-safety actions are refused (`NotInSample`: adding or changing users, invites, roles, password and PIN resets, backups and backup settings). "Set up for real" (`POST /api/guest/leave/`, guest only) puts back `pristine.json` with the same flush-and-load as restores (`backups.replace_all_data`) and removes uploaded files; the set-up wizard follows. After a real set-up guest mode is gone for good. `DEALFLOW_DEMO=1` makes a public demo site: set-up refused, the sign-in page only offers "Continue as guest", firm settings are read-only (`NotOnDemo`), the sample never loads over an install that has users, and the scheduler reloads it daily.
51. **Every option is obvious** (Shobhit, 19 Oct 2026: "assume the user is inherently stupid… all options provided should be obvious"): no action lives only behind hover, an unlabelled icon, a keyboard shortcut or a one-item menu. Buttons carry words (Columns, Filters, Clear filters, Delete, Show menu, Sign out; the notification bell is the one icon-only exception, decision 60); search boxes are real boxes; stage exits are buttons next to "Move to …"; the "+" beside each module in the sidebar is always shown. The card with the person's name at the bottom of the sidebar ("Settings and sign out") opens My preferences, Firm settings (for people who manage users or settings) and Sign out (Shobhit, 19 Oct 2026). My preferences lives inside Settings, under "Just for you", above the firm-wide sections ("For everyone at the firm"); `/preferences` redirects there. One grey line of help sits where an interaction isn't self-evident (dragging cards, clicking rows and column titles, ticking tasks, clicking a stage). Plain words over jargon: "Deleted items" (the Archive), "empty fields". No tours or step-by-step guides.
52. **Bulk actions and merging duplicates** (Shobhit, 19 Oct 2026, every module): list tables have a tick box per row (and one for the page); ticking shows a bar at the bottom with Edit a field, Change stage (pipelines), Add to a deal's tracker (investors), Export, Merge (2–10) and Delete, each shown only when the role allows it. `POST /api/m/<module>/bulk/` (`core/bulk.py`): `action: "edit"` saves `values` on each record exactly like a single edit (validation, stamps, pipeline rules and log entries; for multi-value fields `modes` adds, removes or replaces), reporting records that fail without stopping the rest; `action: "delete"` archives; up to 500 at a time. `POST /api/deals/<id>/tracker/add/` adds investors at Identified and skips ones already tracked. `?ids=` narrows any list or export to chosen records. Merge (`POST /api/m/<module>/merge/`, needs edit and delete; not for tracker entries) keeps one record, applies the values chosen on the side-by-side screen (multi-value fields default to "Combine all"), re-points every link generically through the model's reverse relations and many-to-manys (contacts, outreach, deals, tasks, documents, lead-investor slots), folds a tracker entry into the keeper's when both were on the same deal (its log moves too), moves the log of timeline modules, notes "Merged in: …" on the keeper and sends the others to Deleted items. "Find duplicates" (`GET /api/m/<module>/duplicates/`) groups records by the same rules as the import's warnings (name, website, email, mobile, LinkedIn, two open outreach attempts for one company). Notices sit below dialogs (z-index 190) so they never cover a dialog's buttons.
53. **Input hardening** (edge-case pass, 19 Oct 2026): JSON bodies must be objects (`dealflow/parsers.py`, else 400); NUL characters are stripped from addresses (`dealflow/middleware.py`) and from typed text (`records.text_in`), since Postgres refuses them; ids from requests go through `records.to_id` (1 to 2^63−1, never raises). Whole numbers are 32-bit unless a field sets `min_value`/`max_value` (years: Year founded 1800–this year, Fund vintage 1900–this year+3, shown in the schema as `min`/`max`). Money amounts stay under 10^15 (SQLite keeps 15 significant digits). Long text is capped at 100,000 characters, and a text field's `max_length` never exceeds its column (a test checks every module). Bulk edit ignores switched-off, read-only and unknown fields and refuses when none are left. Import saves each row in its own savepoint and reports rows that fail. Yes/no switches in settings take only true/false. Settings screens with a side list stack on phones; wide tables scroll inside their box, not the page.

54. **Relationships going cold** (Shobhit, 19 Oct 2026; `core/stale.py`): an investor or contact is going cold when "Last contacted" is more than N days ago, or, with no date, it was added more than N days ago. N is separate for investors and contacts (`FirmSettings.stale_investor_days` 90, `stale_contact_days` 60; Settings > Firm; 0 = off; also off when Last contacted is switched off). `GET /api/stale/` lists the ones for the signed-in person: the relationship owner gets theirs, records with no owner go to admins, and only modules they can view. The Reminders bell shows them under "Going cold" with "Contacted today" (sets Last contacted through the normal save, so stamps apply) and "Snooze 30 days" (`stale_snoozed_until`, hidden column), via `POST /api/stale/<module>/<id>/` (needs edit). The bell's count includes them. Lists get on/off buttons from `ModuleDef.quick_filters` ("Going cold" = `?stale=1`, which shows snoozed ones too). The sample firm has a few going cold.

55. **Restricted deals** (Shobhit, 19 Oct 2026; `deals/access.py`): `Deal.restricted` + `Deal.access` (people added by name). A restricted deal is seen by its deal team (lead banker, MDs, VPs, associates, analysts), named people and admins. Everything about it goes with it through `ModuleDef.hide(user)` → Q, applied by `records.visible()` in every generic path (list, detail, lookup, export, search, notes, bulk, merge, duplicates, import duplicate warnings, Deleted items) and in the dashboard, matches and tracker add: its tracker entries, log, documents tagged to it, the outreach attempt it came from, and tasks linked to it (kept for the assignee and creator, with the link shown as "Restricted deal" via `records.hidden_ids`, which uses `core.current` to know who's asking). The company stays visible. Others see placeholders (decision: "show it as Restricted deal"): a deal page answers 403 `code: restricted` with `{id, approvers, request}` (`core.errors.Restricted`, sent untouched), and the deals list/board, a company's deals and an investor's deal history get `restricted: [...]` from `ModuleDef.list_extra` (unfiltered, so filters can't reveal anything); the dashboard counts them as `restricted_hidden`. Changes are `AccessRequest`s: anyone on the team can ask to restrict, lift, or give someone access; an MD on the deal approves (no MD → lead banker → admins; admins can always approve); approvers' own changes apply at once; removing named access needs no approval; anyone can "Ask for access" from a placeholder. Requests show in Reminders and the deal's Access panel; every change is logged on the deal. Only `deals/access.py` writes `restricted` (`Deal.save()` leaves it out of ordinary saves so a stale form can't lift it). Merging deals keeps a restriction and adds everyone who could see a merged deal. Outreach attempts can't be restricted yet (Shobhit: deals only for now).

56. **Audit log** (Shobhit, 19 Oct 2026; `core/audit.py`, `core/audit_middleware.py`, `core/audit_views.py`): every API request (except `/api/health/`) gets one entry: time to the millisecond (firm's clock), person (id, name, email), IP (and X-Forwarded-For), method, path, query, result, duration, a plain-words action ("Edited deal Zeta Pharma"), the request body with anything named password/pin/passphrase/token/secret masked (multipart: size only), and what changed: `records.apply_values` records old → new values in plain words (`core/audit_text.py`), and deletes, restores, permanent deletes, merges, log entries and access changes add their own lines (`core.current.add_change` / `note` / `set_subject`). Entries are sealed one by one for the log's X25519 public key (ephemeral key + HKDF + AES-GCM over zlib), so the server can write but not read; the private key is stored encrypted with a key derived from the **audit passphrase** (scrypt), chosen by Shobhit over a server-held key. Until an admin sets the passphrase, a temporary server key is used; setting it re-seals those entries and deletes the temporary key. Each line carries the SHA-256 of the line before (also bound into the encryption), so deleted, edited, reordered or dropped lines are reported when fetched. Storage is not the database: `AUDIT_DIR` (`DATA_DIR/audit`, or `DEALFLOW_AUDIT_DIR`) holds monthly `YYYY-MM.log` files (compressed when the month ends), `HEAD`, `key.json`, `settings.json`, `pruned.json`; one writer at a time via `flock`. Restores and the guest sample never touch it; backups carry an encrypted copy. Admins only (not in the sample): Settings > Audit log sets or changes the passphrase, starts a new key if it's lost (older entries stay unreadable), sets how many years to keep (default forever; the scheduler removes older months nightly and logs it), and fetches up to 366 days as an Excel file (cells always text) after re-entering their password and the passphrase; five wrong passphrases lock fetching for 15 minutes. The home page reminds admins until a passphrase is set. Roughly 430 bytes per entry.

57. **Custom fields and layouts** (Shobhit, 20 Oct 2026; `core/layout.py`, `core/custom.py`, `core/layout_views.py`, `settings/LayoutSettings.tsx`): Settings > Fields & layout (people with "Manage settings") replaces the old Fields tab. The primary field (`title_field`) stays first and can't be moved, renamed or hidden; required and `always_on` fields can't be hidden. Saving (and switching off) asks for the person's password (`PUT /api/settings/layouts/<module>/`). Switching off brings back the original layout; the custom layout, custom fields and their values are kept, hidden, and return when switched on. Deleting a custom field hides it (`CustomField.active`), with "Bring back". Customisable: Investors, Contacts, Companies, Outreach, Active Deals, Investor tracker; Tasks & Reminders and the Vault only get on/off switches. **Shown through links** (Shobhit): a module can place custom fields of the records it links to (`layout.LINKS`): investors' on contacts and tracker entries, companies' on contacts, outreach and deals (editable there and saved on the company, like the built-in company details), outreach attempts' on deals, deals' on tracker entries; they follow the source module (hidden when it's switched back). Storage: values in each record's `custom` JSON column (`Record.custom`) under `cf_<id>`; layouts in `ModuleLayout` (sections, items, labels, hidden); `ModuleDef.fields` / `.groups` are live properties built from the original lists (`base_fields`, `base_groups`) and cached per worker until `FirmSettings.layout_token` changes (read once per request), so every generic screen (forms, record pages, lists, columns, filters, sorting, search, import, export, bulk edit, merge, audit log) handles custom fields like built-in ones. Numbers are stored as JSON numbers, money with its normalised `value`, multi-values as lists (filtered by a pattern on the list's text, which works on SQLite and Postgres), links as `"module:id"`; merging re-points custom links and deleting for good empties them; links to restricted deals are masked. 58. **Fluid motion** (Shobhit, 20 Oct 2026: "take inspiration from Apple UX principles… fluid, not liquid glass"): all movement lives in `frontend/src/motion.css`; `styles.css` keeps the looks. Springs, not fixed curves: SwiftUI-style `spring(response, damping)` sampled into CSS `linear()` as `--df-spring-smooth` (no overshoot; pages, sheets, sections), `--df-spring-snappy` (menus, indicators, cards) and `--df-spring-bouncy` (presses springing back, ticks, the selection bar), with cubic stand-ins where `linear()` isn't supported; Mantine dialogs, drawers, menus, dropdowns (`Combobox`), segmented controls, the sidebar fold and notices use them through `theme.ts`, arriving on a spring and leaving fast (`exitDuration`). Presses show on the first frame and spring back on release; state changes are transitions (interruptible) rather than keyframes. Page changes are view transitions (`navigation.ts`: the router's history is wrapped and passed to `unstable_HistoryRouter`; each pathname change renders inside `document.startViewTransition` with `flushSync`): the sidebar, top bar and notices stay still; deeper pages slide in from the right, going back up from the left, moving between the sidebar's own pages or sideways is a dissolve (`html[data-nav]`); the clicked list row or board card (`data-hero-row`) grows into the record page's title (`data-hero`, `PageHeader hero`) and settles back on Back, only when both are similar in shape; the sidebar highlight (`.df-nav-pill`) glides between items. Changes of search params (filters, search) don't animate. Scrolling is handled there too: new pages start at the top, Back returns to where you were. Record pages open instantly from list data already loaded (`placeholderData`), then refresh. No decorative entrances: pages and lists no longer fade up or stagger; only content replacing a loading placeholder fades, the sign-in card settles once and dashboard bars grow when their numbers arrive. Dropped board cards land on a spring (`landing()` in `BoardView`). Reduce Motion turns every movement into a short dissolve. Browsers without view transitions navigate without the animation. No glass or blur effects.

59. **Insights without AI** (Shobhit, 20 Oct 2026): stuck alerts, follow-up nudges and win-rate analytics, all computed from the firm's own records. **Stuck** (`core/stuck.py`): an open outreach attempt or deal in one stage longer than the firm usually takes (Shobhit: learned from history). Finished stays per stage come from the log's stage entries (stays interrupted by an exit are left out); with at least 5, a record is stuck after 1.5 × the median, never under 7 days; with fewer, after per-stage starting points (`DEFAULTS`); admins can set any stage's days in Settings > Alerts (`FirmSettings.stuck_overrides`, 0 = never). Final stages and paused or closed records are never stuck. `?stuck=1` on Outreach and Active Deals (a "Stuck" button on lists and boards, works even with reminders off); record pages show a line under the stage bar and board cards a tag (`insights/Stuck.tsx`, rules from `GET /api/insights/stages/`). **Nudges** (`core/nudges.py`, `GET /api/insights/alerts/`, shown in Reminders as "Stuck" and "Follow-ups"): stuck records; tracker investors that haven't moved or had a log entry for N days (one line per deal, `nudge_tracker_days` 10); open records with no edits, log entries or tracker moves for N days (`nudge_quiet_days` 14, not repeated for stuck ones); a meeting or call someone logged with no task added for that record since (to that person, after 2 hours, for 14 days; `nudge_meeting_task`; only for people who can add tasks; "Add a task" opens the task form about the record). Recipients (Shobhit): the lead banker and deal team (MDs, VPs, associates, analysts) for deals, the lead banker for outreach; records with nobody go to admins; only records the person can see. Per-person snoozes (`core.AlertSnooze`): 7 days; a stuck snooze ends if the stage changes; "No follow-up needed" sets a meeting aside until the next one is logged. Settings > Alerts (`/api/settings/alerts/`, manage settings). **Analytics** (`core/analytics.py`, `GET /api/insights/analytics/?period=3|6|12|24|all`, Insights page in the sidebar for anyone who can view Outreach or Active Deals): cohorts by start (outreach) or mandate date (deals); win rate = won ÷ (won + lost), close rate = closed ÷ (closed + withdrawn + dropped), each shown with what it rests on; funnels ("reached" = at or past, exits included); breakdowns by source, sector, transaction type and size band (main currency only); lost reasons; median days to mandate and mandate to close; investors' engagement on trackers (NDA signed or further, among investors on 2+ trackers); how long each stage takes. Everything goes through `records.visible`, so restricted deals count only for people who can see them. Per-banker numbers (Shobhit): only for admins and roles with the new "See team performance" flag (`Role.see_team_performance`). The sample firm has a stuck outreach attempt, a quiet deal with idle tracker investors and a meeting without a task.

60. **Notification bell** (Shobhit, 21 Oct 2026: "remove reminder word, just keep the bell"): the top bar shows only a bell (`tasks/TaskBell.tsx`), outlined when nothing is waiting and filled with a count (red when a task is overdue, orange otherwise) when something is; it shakes when the count goes up (not while the lists first load). Saved reports (`reports.SavedReport`: name, module, config, owner, shared; Shobhit: private unless shared): `GET/POST /api/reports/`, `PATCH/DELETE /api/reports/<id>/` (owner, or an admin for shared ones), `POST /api/reports/<id>/run/` (anyone who can see it, always with their own access); people who can't view a report's module don't see it. 62. **Email from Dealflow** (Shobhit, 21 Oct 2026; `mail` app, `mail/Composer.tsx`, `pages/Campaigns.tsx`, `settings/EmailSettings.tsx`): each person connects their own Gmail or Outlook in My preferences (OAuth with PKCE; tokens Fernet-encrypted with a key derived from SECRET_KEY, so a copied database or a backup restored elsewhere carries no usable tokens and people reconnect). Admins register the install once in Settings > Email (client IDs, secrets stored encrypted and never sent back, Outlook tenant, public address for the redirect URI, password to save) or through `DEALFLOW_GOOGLE_*` / `DEALFLOW_MICROSOFT_*` environment variables. Fewest permissions (Shobhit): Gmail asks only `gmail.send` and its send answer's `SENT` label is the confirmation; Outlook needs `Mail.ReadWrite` + `Mail.Send` (draft, send, read back until it's left Drafts for Sent Items, immutable ids; large attachments go up in upload sessions; the scheduler re-checks for up to two hours, then "Not found in Sent"). All HTTP goes through `mail.providers.TRANSPORT` (stdlib urllib; tests swap in `mail/tests/fakes.py`). **One-to-one**: an "Email" button on investor, contact, company, outreach, deal and tracker pages (needs edit on that record), To/Cc/Bcc with the record's contacts suggested, templates, attachments from the computer (same allowlist as the Vault, kept a week under `DATA_DIR/mail_uploads/`) or the Vault (needs an open Vault), 25 MB in all. Each send (`mail.SentEmail`) writes an `email` log entry (fixed, can't be edited) on the record, each contact it went to and their investor; once confirmed, Last contacted moves to that day through the normal save, never backwards. Investors and contacts now have the interaction log (`timeline=True`). **Campaigns** (mail merge, Shobhit: large, with scheduling) need the new role flag "Send campaigns" (`Role.send_campaigns`); admins see everyone's. People come from ticked contacts or investors ("Email selected"), a list's current filters ("Email these N"), or pickers; contacts with no email, marked "No campaign emails" (`Contact.email_opt_out`, also checked at send time) or with a repeated address are skipped with the reason. Merge fields `{first_name}`, `{firm}`, `{my_name}` and more, with fallbacks `{first_name|there}`; unknown ones are refused. Every campaign email ends with the firm's opt-out line (and a List-Unsubscribe header on Gmail). The scheduler sends each minute up to the per-minute pace (20) within each mailbox's daily limit (Gmail 400, Outlook 1,000, Settings > Email); a provider limit pauses until its retry time, the daily limit until after midnight, a lost permission until the person reconnects (then it carries on); interrupted sends are marked failed rather than resent. Draft, schedule, test to yourself, pause, resume, cancel. Mailboxes can't be connected in the sample firm or on the demo.

63. **Security programme** (Shobhit as CEO, 21 Oct 2026: "the most secure ever"). Target: OWASP ASVS 5.0 Level 2 across the app and Level 3 for sign-in, the Vault and encryption, proven by tests, scanners, documents and an outside penetration test; `docs/security-hardening-brief.md` is the reference, with these decisions where it clashed with V1: **two-step login for everyone, no exceptions** (passkeys or an authenticator app, recovery codes; enrolment before anything else, Just-me installs included); **Vault files encrypted with a firm key that each person's PIN unlocks** (not per-person keys, so shared documents stay shared); **role changes need one admin** (password re-check and audit log, no second approver); **field access per role per field** (can't see / can't edit, enforced everywhere: pages, lists, search, filters, exports, imports, emails, reports, audit); **idle sign-out chosen by admins** (15 min to 8 h, default 30 min, a warning a minute before, 12 h absolute; background polling doesn't count as activity); **antivirus fails closed** (no scanner, no uploads). Our own audit log (decision 56) stays in place of django-auditlog: it already exceeds the brief (encrypted, chained, server can't read it). **S1 baseline (built 21 Oct):** Argon2id only (tests use a light Argon2 in `accounts.validators.TestArgon2Hasher`); passwords 12–256 characters, similarity, common and numeric checks, no reuse of the last 12 (`accounts.PasswordHistory`, hashes only); lock-out in the database (`accounts/lockout.py`, `SignInFailure`: 5 per account by hashed email, 20 per address, 30 minutes; same answers for unknown accounts; admin reset lifts it; the per-process login throttle is gone); sessions (`accounts/sessions.py`): idle limit from `FirmSettings.idle_minutes`, 12 h absolute, expire at browser close, `X-Dealflow-Background: 1` on polling isn't activity, `401 code: session_expired` → the app drops cached data and shows the reason on the sign-in page, `layout/SessionGuard.tsx` warns a minute before and treats typing as activity (`POST /api/auth/session/`); headers (`dealflow/security.py`: CSP without inline or outside scripts, Permissions-Policy, CORP, `no-store` on the API) plus Django's (DENY, nosniff, same-origin referrer and COOP); `DEALFLOW_HTTPS=1` turns on secure `__Host-` cookies, redirects and HSTS (preload opt-in, W021 silenced with the reason), `DEALFLOW_BEHIND_PROXY=1` trusts forwarded headers; `ALLOWED_HOSTS` defaults to localhost; invite links stored as SHA-256 and shown once, 72 hours (overrides decision 14's 7 days); request bodies 5 MB; Settings > Security (admins). `CHANGELOG.md` records the security effect of each change.
